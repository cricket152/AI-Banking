# 账单洞察与疑似订阅

本轮按用户授权补齐 T10 / T11：账单分类与时间对比、异常支出线索、可分页核对的原始流水，以及疑似订阅识别和显式确认登记。全部基于本人的虚构流水，不新增依赖、数据表或迁移；不接入真实金融渠道。

## 页面验收

1. 重启服务并刷新，进入“账单洞察”。选择开始与结束日期（界面包含结束当天）；也可选本月至今、上月或今年至今。单次最多 366 天。
2. 核对消费、退款、净支出、收入以及单独列出的转账。展开分类流水或全部流水，逐页核对；分类同时提供本期与前期依据。
3. 对比区间为紧邻本期之前的相同自然日天数，不是固定上月或同比。例如 10 月 1–29 日对比 9 月 2–30 日。没有历史记录时明确说明无法判断增长或节省，不计算无依据的百分比。
4. 异常线索有两种：非转账单笔支出不少于 1000 元；前期同分类至少三笔支出时，本期单笔超过前期同类中位数三倍且不少于 100 元。中位数为排序后靠下的中位数（偶数笔时取较小的中间值）。可展开具体流水，并从前期分类流水复算基准。这些规则不能判断欺诈，未命中不代表所有交易安全。
5. 在“业务办理 → 订阅管理 → 疑似订阅”展开证据。识别要求：最近一年同账户、同商户至少三次等额非转账支出，相邻间隔均为 25–35 天，最近 45 天有扣费。不匹配、数据不足或已经登记（含已取消）的商户不推荐。
6. 点击“核对并登记”，再次核对账户、金额和每笔流水。未勾复核、关闭或按 Escape 不登记；勾选后明确确认才登记。确认仅加入模拟管理清单，不扣款、不创建授权、不取消订阅。
7. 登记后展示“流水推断后经你确认”和预计下次日期。估计按最后一笔的东八区日期顺延一月、月底取下一月最后一天，不保证真实扣费日。取消仍走已有独立确认或明确预授权；取消不退款。

默认用户样本每个订阅仅有一笔扣费，不能满足三次周期识别，因此疑似列表可能为空。不会为了演示向已有账户添加或改写流水。浏览器验收使用独立合成数据库；不把空候选伪装成已发现订阅。

## 接口与工具

- `GET /api/bank/reports?start=YYYY-MM-DD&end=YYYY-MM-DD`：保留原字段，追加 `comparison`（前期范围、笔数、消费、净支出、分类变化）和带金额 / 基准的 `possible_anomalies`。本期与前期在同一数据库事务内读取。
- `GET /api/bank/reports/entries`：相同闭开日期范围，可选 `category`、`entry_id`，`offset>=0`、`limit=1–50`（默认 20），返回本人 `entries`、`total`、`next_offset`。无权访问的流水不会返回。
- `GET /api/bank/subscriptions`：原登记列表保留，`inferred_candidates` 提供候选 ID、证据摘要、原始流水、间隔、规则和预计日期。
- `POST /api/bank/subscriptions/candidates/{candidate_id}/confirm`：仅接受 `evidence_digest` 和严格布尔值 `acknowledged=true`。需要有效会话、同源和 CSRF。服务端在事务中重新识别并校验证据，变化或不再符合规则返回 `SUBSCRIPTION_EVIDENCE_CHANGED`（409）；成功登记写入原 `bank_subscriptions`，`source=inferred_confirmed`，证据引用写原 `bank_events`。同一证据的重复 / 并发请求只登记一次，回放不会恢复已取消项。
- Agent 保留原十个工具及顺序，追加只读 `get_billing_entries`。账单汇总与订阅查询沿用原工具并增强说明。Agent 没有登记工具，不能用聊天中的确认代替界面确认，也不能拿候选 ID 申请取消。

## 验证边界

专项测试见 `tests/test_insights.py`，覆盖统计与证据、分页、历史基准、候选排除、账户隔离、CSRF、严格输入、证据变化、并发与重复登记、取消边界及月份末日。真实模型的选择工具和语义可靠性需要另行验收；自动化与浏览器使用隔离虚构数据，不代表真实银行或生产安全审计。
