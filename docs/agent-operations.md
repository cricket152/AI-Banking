# Agent 受控操作与多步骤任务

当前实现覆盖账单查询、登记订阅取消和模拟转账的组合任务。默认逐笔人工确认；用户也可创建范围和额度明确的预授权，再在当前对话中显式选择使用。模型负责澄清、查询、提出操作及核对回执；应用负责授权检查和执行。资金契约见 [模拟银行业务](banking-services.md)。

## 页面使用步骤

1. 重启本地服务并刷新页面，登录自己的模拟用户。已有数据库需先按银行契约完成显式升级；本次功能不增表、不自动迁移。
2. 打开“业务办理”，可手动转账、查看并取消登记订阅、创建或撤销预授权，以及查看最近 50 条操作。准备操作后余额与订阅不变。
3. 人工确认弹窗展示后端生成的账户、收款人、金额、费用、订阅和期限。核对后主动勾选复核框，再点击批准；拒绝不执行，关闭弹窗也不批准。默认确认期限 300 秒。
4. 打开“AI 助手”，默认“逐笔人工确认”。例如输入“先查询我的订阅支出，再从日常账户向本人储蓄账户转账 100 元，最后取消云音乐订阅”。信息不完整或目标有歧义时应先澄清，不猜测账户或金额。
5. 助手准备操作后显示操作卡片。点击确认并批准后，页面自动通知助手回查原操作，再继续原目标中的下一步；每个新操作仍需独立确认。拒绝、失败、过期或结果未知时停止后续步骤。
6. 如需自主执行，在“业务办理”逐项填写付款账户、允许收款人、累计上限、单笔上限、最低余额、有效期、操作种类和允许取消的订阅，并重新输入登录密码创建预授权。
7. 创建授权后，可直接在该授权卡片点击“在本对话启用”；也可回到助手的“执行方式与预授权”，选择后立即生效（无需再点应用）。“查看授权详情”会跳到业务办理并在表单中回填该授权的账户、操作、收款/订阅范围、额度与截止时间，便于核对。截止时间按年/月/日/时/分五段填写（分隔符固定），默认东八区当前时间+1 天，必须晚于当前时间。
8. 提出明确任务。范围内操作由应用复核并执行，无逐笔确认弹窗；超范围、超额度、授权失效或余额不足时停止，不能通过聊天扩权或拆单。处理原因后需要用户在界面重新明确选择执行策略，才能解除该类策略暂停。
9. 刷新只恢复会话、策略和后端状态，不自动调用模型或再次付款。策略恢复完成前禁用发送和资金按钮；查询失败时先刷新。结果待核实时只核对原操作，不换编号重发。

离线模式仍是查询演示，不能自由规划写任务。真实模型需配置支持工具调用的供应商；不要将页面“模型模式”当作供应商已经联通的证据。

## 工具与权限

原五个工具 `list_accounts`、`get_transactions`、`list_payees`、`list_subscriptions`、`get_billing_summary` 顺序不变，追加：

| 工具 | 模型参数 | 应用行为 |
| --- | --- | --- |
| `prepare_transfer` | `source_id`、`payee_id`、整数分 `amount_minor`、`currency="CNY"` | 人工模式创建待确认操作；显式预授权模式下准备并经原执行器复核执行 |
| `prepare_subscription_cancellation` | `source_id`、`subscription_id`、`currency="CNY"` | 同上；取消未来续费不退款 |
| `get_operation` | `operation_id` | 查询本人持久操作状态与回执 |
| `list_cards` | 无 | 返回本人模拟借记卡（账户、脱敏卡号、状态、日限额）；仅查询，不支持申请、调额、冻结或挂失 |
| `list_wealth_products` | 无 | 返回本地模拟理财目录（类型、风险等级、起投金额、模拟收益区间）；仅查询，不支持申购、赎回或资金划转 |

理财与卡片目前只有查询工具，没有对应写操作；模型不得暗示已办理或可代办。

标识必须来自查询结果；参数严格校验。模型不能传入身份、`task_id`、`step_key`、`mode`、`grant_id`、密码或确认凭证，也没有批准、创建授权、执行和对账工具。聊天中说“确认”不能代替独立弹窗确认。会话有效性、所有者、额度、余额、状态和幂等检查均由后端执行。

`agent_funds_access=false` 表示不向模型暴露直接执行权限；`agent_operation_preparation`、`agent_preauthorized_execution` 表示相应能力配置就绪，不代表供应商连通。账户快照保留兼容字段 `funds_mode=READ_ONLY`；模型上下文另附当前对话实际执行策略。

## 多步骤与幂等

- 服务端核验对话归属，用对话 UUID 派生稳定任务请求编号。步骤由操作种类和业务参数摘要派生，模型不能选择或换编号。
- 同一对话、同种业务和相同参数始终复用原操作，即使已成功也不再执行。兼容旧版 `primary_intent`，升级后不复制已有交易。
- 只有已有步骤全部成功，才能创建不同参数的下一步；该限制在准备事务中检查，防止并发绕过。待确认时改变参数返回冲突并保留原操作。
- 相同参数的第二次独立业务需要用户明确新建对话；新对话是新业务，不可用来自动重试旧付款。
- 拒绝、失败、过期、执行中和未知结果阻止新步骤。预授权准备或执行的策略错误持久化为任务暂停，防止模型改参数继续尝试；重新选择策略不会重置累计支出，也不会把原人工操作变成自动批准。
- 策略选择与暂停复用 `bank_events`，操作与步骤复用原银行表，无新增依赖或迁移。预算、账本和执行恢复仍使用原确定性执行器。

## 接口与恢复

| 接口 | 用途 |
| --- | --- |
| `GET /api/bank/operations?limit=50&task_id=...` | 本人操作列表，最多 100 条；任务筛选校验归属 |
| `GET /api/conversations/{id}/policy` | 当前对话策略及授权公开属性 |
| `POST /api/conversations/{id}/policy` | 严格对象 `mode`、`grant_id`；同源、CSRF、归属及授权有效性校验 |
| `POST /api/conversations/{id}/continue` | 严格对象 `operation_id`；仅成功且属于原任务的操作可续办 |

聊天成功、缓存和历史提供 `operation_task`；历史同时提供 `execution_policy`。每轮模型重新读取银行检查点。成功操作的续办请求 ID 由原操作派生，重复续办回放缓存而不再次调用模型；UI 对缓存不重贴可能过时的待确认文案，操作卡片始终读后端。

准备后模型失败、提交后响应丢失或重启时，刷新可找回原操作。未知结果保留预占并停止后续操作，通过业务页显式核实；不凭聊天文案报告成功，不自动重新付款。

当前上下文由预算装配器管理：系统提示与工具定义是稳定前缀，始终完整保留；最近 `MODEL_CONTEXT_RECENT_TURNS`（默认 12）个完整成功回合保持原样，更早的回合压成确定性摘录（保留轮次编号、最初目标与答复要点，并注明省略数量），`bank_state` 与最新问题固定在末尾。摘录不是指令，不能授予授权或替代后端查询；资金、额度与策略始终回查后端。单次工具结果超过 `MODEL_TOOL_OUTPUT_CHARS`（默认 6000 字符）会截断并提示缩小范围或分页。预算无法安全容纳时返回 `CONTEXT_BUDGET_EXCEEDED`，本轮不执行新操作并保留银行检查点；原目标已不在上下文时必须先澄清。单轮最多 8 次模型请求、每次最多 4 个工具调用、整轮 90 秒。预算参数见 `.env.example`，实现见 `src/ai_banking/context.py`。

## 验证边界

自动化覆盖两种模型协议的“账单 → 取消 → 转账”、人工批准后续办、预授权累计与暂停、越权 / CSRF、重复及并发、拒绝、响应丢失、未知结果和旧步骤兼容。实际浏览器验证了手动转账、拒绝取消、两步逐笔确认、预授权自动转账、超限不扣款、刷新恢复与移动宽度布局。

上述验证使用隔离 SQLite、模拟模型响应和真实银行执行器，没有读取真实 Key 或调用供应商。用户此前确认 T14-A 测试通过；本次新闭环的真实模型验收、队友审查、完整 T15 和竞赛全项验收仍待完成。

后续已按用户要求增加真实模型提示词评测，使用隔离数据和当前供应商，结果及局限见 [Agent 提示词评测](agent-evaluation.md) 和项目状态。新增 `MODEL_RESPONSE_INCOMPLETE`：供应商明确标记未完成时停止本轮，不执行该响应里的工具；先查询既有操作，不重新付款。这些有限样本不代替人工全项验收。
