# 项目需求

## 项目目标

交付一个可在开发者本机启动、可复现演示并可测试的 AI Banking 原型。当前功能范围依据用户提供的竞赛任务图片确认；正式竞赛规则和评分要求仍以 [比赛要求](competition.md) 为准，尚未核实的规则不作推断。

## 目标用户与使用方式

| 项目 | 内容 |
| --- | --- |
| 目标用户 | 需要通过中文对话查询或模拟办理日常银行业务的个人用户 |
| 用户问题 | 在多个账户页面间查找常见功能、理解账单或管理重复扣费 |
| 输入与输出 | 输入自然语言；返回意图、执行计划、工具状态、结果和必要风险说明 |
| 使用入口 | 本地 Web 工作台及本机 JSON HTTP API |
| 数据范围 | 虚构的个人、账户、交易、联系人、卡片、订阅和理财产品样例 |

## 核心需求

| 编号 | 场景 | 验收范围 |
| --- | --- | --- |
| REQ-01 | 智能转账 | 支持联系人姓名、手机号或备注匹配；即时转账和预约转账；支持 AA 总额分摊并创建收款单 |
| REQ-02 | 账单分析 | 按消费类别汇总；提供月度汇总和本年已记录交易汇总；标记待人工核对交易，不将标记表述为欺诈结论 |
| REQ-03 | 理财操作 | 展示产品风险、演示年化和波动率；按稳健偏好排序；支持确认后模拟申购和赎回，并提示风险 |
| REQ-04 | 卡片管理 | 支持演示数字卡申请、信用额度与单日限额修改、卡片锁定和解锁 |
| REQ-05 | 订阅 / 代扣管理 | 展示周期费用和下次扣费日期；设置续费提醒；取消后续续费 |
| REQ-06 | 跨场景联动 | 在生日日期预留指定金额，并提前两天创建鲜花、蛋糕提醒；不自动下单 |
| REQ-07 | 安全确认 | 任何会改变模拟资金或账户状态的操作先展示明细，只有用户确认后才执行；拒绝操作不改变状态，待确认操作只能执行一次 |
| REQ-08 | 本地运行 | Python 标准库启动 Web 工作台和 JSON API；服务绑定回环地址，不需要外部密钥或服务 |

## MVP 范围

- 完整演示以上六类场景，并提供可点选的工作台入口和中文对话。
- 对话解析采用本地规则和已登记实体匹配；无法识别或缺少必需信息时询问补充，不猜测收款人或金额。
- 账户、交易和产品数据仅为样例；服务重启后恢复初始状态。
- 使用 Python 标准库、原生 HTML / CSS / JavaScript 和 `unittest`，不安装生产依赖。
- 运行和测试命令见 [README](../README.md)。

## 非目标与限制

- 不连接真实银行、支付渠道、银行卡网络或证券交易系统。
- 不进行真实转账、申购、赎回、订阅取消或礼物下单；相关结果只更新内存模拟状态。
- 不接入外部大模型、MCP 客户端、移动 App、身份验证或持久化数据库。
- 本地规则解析仅覆盖演示中定义的中文意图和实体，不等同于通用语言模型。
- 不将演示收益、异常标记或联系人数据视为真实金融、风控或个人信息结论。

## 验收标准

- 可按 README 在无第三方依赖的环境启动；浏览器总览和六类功能页可访问。
- 六类场景各自能完成查询或生成操作计划；资金或账户状态修改都须明确确认。
- 转账、预约、AA 分摊、生日预留、申赎、卡片限额和订阅状态具备金额或状态边界校验。
- API 拒绝无效 JSON、超长需求文本和非本地服务绑定；静态资源不能读取工作区文件。
- 自动化测试覆盖意图解析、操作确认 / 拒绝、主要业务边界及 HTTP API。
