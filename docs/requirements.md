# 项目需求

## 项目目标

按 [分步执行计划](execution-plan.md) 构建一个满足已核实竞赛要求、可验证且可复现的 Agent 项目。竞赛原文与未知限制统一维护在 [比赛要求](competition.md)。本文件记录项目选择，不把项目设计冒充为官方规则。

## 目标用户与场景

| 项目 | 内容 |
| --- | --- |
| 目标用户 | 使用自然语言办理模拟银行业务的个人用户 |
| 业务环境 | 自建模拟银行，使用虚构账户、收款人和交易；不接入真实银行或支付渠道 |
| 用户入口 | 第一版选定单一 Web 入口；竞赛是否要求 APP / IM 等特定渠道待核实 |
| 数据来源 | 可复现的合成测试数据；真实个人或银行数据不进入项目 |

## MVP 范围

执行计划选择三个业务场景，配一个跨场景闭环：

| 编号 | 场景 | 第一版目标 |
| --- | --- | --- |
| R1 | 账单分析 | 从后端流水计算分类、异常提示和月度 / 年度报告；金额结果可回查流水依据 |
| R2 | 订阅管理 | 区分登记订阅与流水推断候选；支持续费提醒及经确认的取消操作 |
| R3 | 智能转账 | 在人工审批或范围明确的预先授权下，向指定收款人发起模拟转账；由后端验证额度、余额和幂等 |
| R4 | 跨场景闭环 | 查询订阅支出、取消获授权的订阅，再从当前可用余额向指定账户转账；各步骤可单独核对和恢复 |

R4 是项目计划选定的“订阅查询 / 取消后转账”闭环，与官网生日需求预订示例、用户截图中的生日资金预留示例均不同。是否符合竞赛跨场景验收要求需在完整规则核实后确认。

### 授权与资金约束

- 人工审批和预先授权共用同一资金执行器。Agent 只能创建意图，不能直接扣款或扩大授权范围。
- 预先授权需绑定付款账户、币种、有效期和允许收款账户；剩余额度按累计支出口径计算。
- 执行中及结果未知的操作继续占用额度；成功支出计入累计额，收款或退款不自动补回额度。
- 预授权周期、有效期、单笔上限、累计上限、最低余额、费用处理及订阅取消授权范围均为 `TODO: 待确认`。参数确认前不实现对应自动执行路径。
- 金额使用整数分和明确的 `CNY` 币种，禁止浮点数参与资金计算。

## 核心验收用例

| 场景 | 可验证结果 |
| --- | --- |
| 账单汇总 | 给定固定流水和日期范围，分类合计与逐笔流水可复算；退款、转账的统计口径需在 T10 锁定并覆盖测试 |
| 订阅识别 | 明确标注登记订阅与流水推断候选；未确认的取消不产生状态变化；重复取消只有一次业务效果 |
| 人工转账 | 展示后端生成的准确金额、付款账户和收款人；未确认、拒绝或确认过期时账本不变 |
| 预先授权转账 | 仅允许策略范围内的账户、收款人、币种与时间；并发和重复请求不突破累计预算或重复扣款 |
| 跨场景任务 | 每一步记录操作编号和状态；部分成功、重启或重复消息不重做已完成的资金操作；未来节省金额不作为当前入账 |
| 身份隔离 | 用户身份来自服务端认证上下文；客户端、聊天内容和模型输出不能指定或覆盖身份 |

具体余额、授权额度、时间窗口、性能和评分阈值必须有已确认依据；不得用样例值伪装比赛规则。

## 第一版非目标

- 理财申购 / 赎回与产品推荐、卡片申请 / 管理、真实资金或真实支付接口。
- 定时转账、AA 收款、MCP、多 Agent、动态工具加载、RAG 和用户长期记忆。
- 同时建设 Web、原生 APP 及多个 IM 入口。
- 以模型摘要、聊天记录或客户端状态代替账本、授权或操作结果。

官网将定时转账与 AA 收款列在“智能转账”场景中，而执行计划暂不纳入第一版；这可能影响该场景是否被评为完整覆盖，须由团队结合详细赛规确认。官网跨场景示例为识别生日并自动预订服务，用户截图补充了 1000 元资金预留和提前两天购买，执行计划则选择订阅取消后转账。须由团队结合完整赛规确认要实现的精确流程；未确认前不声称完整覆盖该官方场景。

## 验收标准

- 第一版覆盖三个经团队确认的核心场景及一个可恢复的跨场景闭环。
- 未授权资金操作没有账本副作用；同一业务操作不会重复记账；借贷账目平衡。
- 用户隔离、并发余额与授权额度、崩溃恢复、未知结果和提示注入相关检查全部通过。
- 流水统计有依据；取消操作结果可查询；所有演示数据可从干净环境复现。
- 详细竞赛规则未核实的要求保持待确认，不声称达到未经定义的评分或交付指标。

## 待确认事项

1. 官方完整参赛规则、评分与交付要求，以及计划中的三场景是否满足最低验收。
2. 定时转账和 AA 收款是否必须纳入智能转账场景的第一版验收。
3. 两位成员的账号、职责、代码审查人及责任边界。
4. 模型供应商、模型版本、网络 / API 配额、费用与评测环境。
5. 预先授权的额度周期、有效期、单笔上限、最低余额、费用和撤销语义。
6. 订阅信息来源、取消接口边界、用户认证凭据及公开仓库的保密 / 许可要求。
