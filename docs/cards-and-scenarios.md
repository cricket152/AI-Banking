# 卡片管理与跨场景计划

本轮按用户要求增加两项本地模拟 MVP，全部使用既有数据库与事件表，不新增表、不连接真实卡组织、外部商户或定时任务。

## 卡片管理

1. 重启服务并刷新，进入“业务办理 → 卡片管理”。
2. 每个模拟账户默认派生一张借记卡；可展开“申请一张模拟卡”，选择绑定账户、卡类型（借记卡/信用卡）、日限额并重新验证登录密码。
3. 卡片列表显示账户、脱敏卡号、尾号、类型、状态和日限额；修改限额、冻结/解冻、挂失都需要在该卡片行重新输入登录密码。
4. 挂失是终态；挂失后不能调额、解冻或再次申请该卡的业务。所有操作只写本地事件，不改变账本、余额或真实信用记录。
5. Agent 只保留 `list_cards` 查询；模型不能申请、调额、冻结或挂失，避免聊天文本绕过再认证。

验收点：

- 未登录、跨用户、错误密码、错误状态/限额都被拒绝；
- 操作只影响本人卡片，不产生资金流水；
- 申请/调额/冻结/挂失刷新后保留；
- 操作记录与卡片状态来自后端，不以模型回复为准。

## 跨场景计划（纪念日 / 生日）

1. 进入“业务办理 → 跨场景计划”，选择生日/纪念日/自定义，填写名称、日期、预算、付款账户和模拟商户/收款人，保存计划。
2. 计划只保存日期、预算和对象，不扣款、不冻结资金、不联系商户，也不自动定时执行。
3. 临近日期（0–2 天）时按钮提示“可模拟下单”；点击后后端用既有转账准备事务创建一笔**待确认的模拟转账**，必须再走人工确认单或明确预授权。
4. 模拟下单不连接鲜花/蛋糕等外部商户，不能当作真实订购；它只是跨场景联动（日历 + 预算 + 转账）的可审计演示。
5. 可取消计划；已下单的计划不能取消，需按原操作状态核对。

验收点：

- 创建/下单/取消都按本人隔离，跨用户 404；
- 下单前不产生账本流水，下单只创建 `awaiting_confirmation` 操作；
- 相同计划重复下单复用同一个操作编号，不重复扣款；
- 预算不足、过去日期、越权对象被拒绝；
- 刷新后计划、操作状态和回执保留。

## 代码与测试

- 后端：`banking/cards.py`、`banking/scenarios.py`、`banking/api.py`；
- 前端：`web/cards.js`、`web/scenarios.js`，并接入 `banking.js` 的后端数据加载；
- Agent：`list_cards` 改为读取动态卡片状态；卡片写操作不暴露给模型；
- 测试：`tests/test_cards.py`、`tests/test_scenarios.py`；
- 仍为本地模拟：没有真实卡组织、信用评分、外部商户、定时任务或后台无人登录执行。

## 理财模拟申购/赎回

- 页面“业务办理 → 理财操作”展示模拟产品与当前模拟持仓；
- 选择产品、申购/赎回、账户与金额，提交后创建待确认操作，不会立即扣款或入账；
- 人工确认后：申购扣减模拟账户余额并增加持仓；赎回先校验持仓，再把金额回到账户；
- 不连接真实产品、净值、收益分配或投资建议；持仓由事件记录，余额与 entries 保持一致。
