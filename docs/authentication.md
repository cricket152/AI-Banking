# T01-A：身份认证与会话契约

定稿日期：2026-10-22（Asia/Shanghai）。状态：已按用户追加的运行环境与前端授权实现本地认证及访问隔离，测试证据见 `PROJECT_STATUS.md`。本文件仍是 T03 契约，不表示完整 G0 或生产安全审计通过。

## 1. 范围与决定

第一版面向单进程、单一同源 Web 入口的模拟银行，采用本地模拟用户、密码认证、SQLite 持久化会话和不透明 Cookie。账户身份、会话有效性与资源归属均由服务端判断。

不引入第三方登录、JWT、浏览器存储中的 Bearer Token、公开注册、短信、邮箱找回或真实银行身份认证。登录只证明身份，不授予转账权限；人工审批和预先授权在 T08 / T09 单独实现。

运行主机及本地管理人员属于可信边界；本契约不承诺防御主机或服务进程已被控制的情况，也不是生产银行认证方案。

## 2. 模拟用户与凭据来源

- 模拟用户由开发者在本机使用管理命令创建，不提供公开注册 API，不自动生成可登录的默认账号或固定密码。
- T03 的命令为 `python -m ai_banking.auth.cli create-user <username>`、`reset-password <username>` 和 `disable-user <username>`；运行步骤见 [本地开发](local-development.md)。
- 创建或重置密码使用 `getpass` 交互输入并再次确认。密码不接受命令行参数，不写入输出、日志、种子文件、示例配置或仓库。管理命令只访问已配置的本地数据库，不暴露成 HTTP 接口或 Agent 工具。
- 用户名统一去除首尾空白并转为 ASCII 小写，再校验 `[a-z][a-z0-9_]{2,31}`；创建与登录使用相同规则。重名创建失败，不覆盖现有用户。
- 按用户本地测试要求，创建与重置密码接受 1–128 个 Unicode 字符，与登录及再认证接口一致；不执行去空格、大小写转换、Unicode 归一化或静默截断，不要求固定字符组合。
- 密码散列选定 Argon2id，使用 `argon2-cffi` 的高层密码 API，不自行实现加密算法。基线参数为内存 19456 KiB、迭代 2、并行度 1，随机盐 16 字节、输出 32 字节；保存含算法与参数的编码散列。
- 新依赖在实现密码验证时说明并引入。选用维护中的 Argon2 实现是为了避免自制密码存储；标准库 scrypt 是可评估的替代方案，但不得在运行时因依赖缺失自动降级。
- 不存在的用户名使用同等参数的虚拟密码散列执行验证路径，已停用、未知用户和密码错误均返回相同登录错误；不承诺网络响应时间完全一致。
- 变更密码或停用用户时，增加该用户的 `auth_version`，在同一事务内撤销其全部会话。重新散列同一密码本身不视为修改凭据。

测试至少使用两个独立用户。测试密码由测试代码临时生成，不复用真实密码，不附带在正常运行可访问的演示数据中。

## 3. 后端记录与身份上下文

以下是字段职责契约，不是数据库迁移；T03 只创建认证需要的表，不提前创建银行账户和资金表。

| 记录 | 最小内容 |
| --- | --- |
| `users` | 不可变 `user_id`、唯一规范化用户名、密码散列、启用状态、`auth_version`、创建时间 |
| `sessions` | 内部记录 ID、唯一 `token_digest`、会话种类、可空 `user_id`、CSRF 随机值、认证版本、创建时间、最近活动时间、绝对失效时间、撤销时间 |
| 登录限制记录 | 规范化用户名与连接来源对应的失败窗口、次数和阻止截止时间；并发更新受事务保护 |

- 会话 Cookie 使用 CSPRNG 生成的 32 字节随机秘密，经 Base64URL 编码后发送。数据库只保存其 SHA-256 摘要用于查找，不保存原 Cookie；内部记录 ID 不能代替 Cookie 认证。
- 会话分为 `preauth` 和 `authenticated`。预认证记录只支持登录防护，不能访问受保护资源；只有成功验证密码后才能创建认证会话。
- CSRF 值是与会话绑定的独立随机值，可存于服务端会话记录并经同源 JSON 响应提供给浏览器；它不能代替会话 Cookie，不进入模型、URL 或日志。
- 请求认证时同时检查记录存在、未撤销、未超时、用户启用及认证版本一致；数据库查询失败时返回服务不可用，不降级为匿名之外的身份或测试身份。
- 服务端构造只读 `AuthContext`，仅包含 `user_id`、内部会话记录 ID、认证时间和认证版本。密码、Cookie、密码散列和 CSRF 值都不传给业务工具或模型。
- 数据库和测试数据库路径必须显式隔离。清理过期记录不能被用来恢复撤销状态；会话记录和认证版本应在重启后继续有效。

## 4. 会话生命周期与项目默认值

以下均为本项目模拟环境的初始配置，不是比赛规则或通用银行安全标准。调整时需同步文档和边界测试，不能由请求体或模型覆盖。

| 项目 | 默认值 / 行为 |
| --- | --- |
| 预认证有效期 | 创建后 5 分钟，不可滑动延长 |
| 认证会话闲置超时 | 最近有效用户活动后 15 分钟 |
| 认证会话绝对有效期 | 登录成功后 8 小时，不因活动延长 |
| 登录失败限制 | 同一规范化用户名 5 分钟内失败 5 次，暂阻止 5 分钟；同一连接 IP 5 分钟内失败 20 次同样限制 |
| 预认证分配限制 | 同一连接 IP 5 分钟内最多创建 60 个预认证记录，避免无限分配 |
| 会话范围 | 同一用户可有独立浏览器会话；退出只撤销当前会话，停用或密码重置撤销该用户全部会话 |
| 记住登录 | 第一版不提供；Cookie 不设置持久化 `Max-Age` / `Expires`，实际有效性仍由后端决定 |

- 服务端使用 UTC 时间；在 `now >= expires_at` 或闲置时长达到上限时立即判为失效。测试注入可控时钟，不依靠真实等待。
- 最近活动只由通过认证与请求安全检查的直接用户业务请求更新；轮询状态、获取认证状态、获取 CSRF 值、Agent 内部工具调用和后台任务不刷新闲置计时。是否属于用户业务请求由受信应用入口决定，不能采信客户端自行声明。
- 登录成功后撤销预认证会话，重新生成认证 Cookie 与 CSRF 值，禁止沿用登录前的会话秘密。已有有效认证会话再次请求登录返回 `409 ALREADY_AUTHENTICATED`，切换用户先退出。
- 退出在后端持久化撤销并清理 Cookie。关闭浏览器不是可靠的后端退出信号，不替代闲置和绝对超时。
- 每个受保护请求都检查会话状态。未来资金执行器仍须在提交动作前复核身份与操作授权；在撤销生效后不得提交新的受该会话授权约束的动作，已提交操作只能核实结果，不能假定回滚。
- 登录限制按真实连接来源计数，初版不信任客户端的 `X-Forwarded-For`。失败窗口持久化，重启或换 Cookie 不清零；窗口结束后允许重试，避免永久锁死。

## 5. Web 传输与最小 API

### Cookie、来源与缓存

- Cookie 名称为 `ai_banking_session`，设置 `HttpOnly`、`SameSite=Strict`、`Path=/`，不设置 `Domain`。默认仅在 HTTPS 下发送，设置 `Secure`。
- 仅显式选择本地 HTTP 配置并绑定 loopback 时，才允许关闭 `Secure`；非 loopback 地址或未显式选择本地配置时必须拒绝此降级。不能因 HTTPS 配置失败自动回退 HTTP。
- 应用启动时配置唯一允许的 Origin（包含 scheme、host、port）及对应 Host；不从未经验证的 Host 或代理头推导可信来源，不开放跨域凭据访问。
- 所有状态变更端点仅接受 `application/json`，要求 Origin 与配置完全匹配，并验证 `X-CSRF-Token`；缺失或不匹配的 Origin / CSRF 检查失败即拒绝。SameSite 只是额外保护。
- 获取 CSRF 的 GET 请求也检查 Host，必须携带自定义 Header `X-Requested-With: AI-Banking`，且拒绝跨域 Origin 或 `Sec-Fetch-Site: cross-site`。不符合条件时不设置或替换 Cookie，避免跨站导航覆盖已有登录；不通过 JSONP、URL 参数或跨域响应暴露令牌。
- 认证响应统一设置 `Cache-Control: no-store`。请求日志与错误处理屏蔽密码、Cookie、CSRF 及密码散列；客户端不将会话或 CSRF 值写入 localStorage。

### 接口契约

| 接口 | 请求与结果 |
| --- | --- |
| `GET /api/auth/csrf` | 通过自定义 Header 与来源检查后，无有效会话时建立受限预认证会话，返回对应 `csrf_token`；已有有效会话时返回该会话的 CSRF 值，不延长会话、不提升身份 |
| `POST /api/auth/login` | 使用预认证 Cookie 与 CSRF，只接受 `username`、`password`；验证成功返回最小用户信息、认证会话到期时间和新 `csrf_token`，通过 Set-Cookie 设置新秘密 |
| `GET /api/auth/me` | 认证后返回本人 `user_id`、用户名及会话到期信息；不接受目标用户参数，不延长会话 |
| `POST /api/auth/logout` | 有效会话须校验 Origin 和对应 CSRF，撤销当前记录并清理 Cookie，返回 204；会话已失效或缺失时仍校验 Origin，清理 Cookie 后返回 204，不影响其他会话 |

获取 CSRF 建立的只是技术会话，不是业务授权。禁止 GET 端点执行退出、转账、修改模式或其他业务写操作。测试客户端必须按同一协议提供 Origin、Cookie 和 CSRF，不能设置跳过安全检查的运行开关。

## 6. 资源隔离与模型边界

- 用户查询或变更资源时必须使用 `AuthContext.user_id` 限定归属；只知道资源 ID、用户名或会话记录 ID 不构成访问权限。
- 身份字段不属于业务请求和工具输入。请求体中的 `user_id`、`owner_id`、角色或权限字段按未知字段拒绝；客户端自报身份 Header、聊天内容和模型输出不能进入身份解析流程。
- 跨用户资源和不存在资源统一返回 404，不泄露另一位用户是否拥有该记录。
- 第一版只支持普通用户，没有通过模型、请求参数或默认账号获取管理员身份的途径。本地管理命令依赖主机权限，不属于 Web 角色。
- T03 以测试专用资源存根验证归属隔离，不提前实现 T04 银行账户。后续资源仓储必须复用同一身份上下文和访问检查。
- 需要模型参与的请求先由应用层认证，再传入非敏感业务信息；Agent 不能接触登录、退出、用户管理或后续重新鉴权接口。
- 授权模式变更、提高额度或新增收款范围不属于登录 API；T08 / T09 需实现绑定具体动作的授权及必要的重新鉴权，不能仅凭登录时间判断资金权限。
- 后台预先授权是否在普通退出或闲置过期后继续，需要在 T09 明确，T03 不预建后台执行权限。用户停用、凭据安全性重置后的委托撤销，以及已提交交易核实，也必须在 T09 接入并验证。

## 7. 错误语义

| HTTP / 代码 | 行为 |
| --- | --- |
| 401 `CREDENTIALS_INVALID` | 未知、停用用户与密码错误统一登录失败；不包含用户名存在性或停用细节 |
| 401 `AUTH_REQUIRED` | 受保护请求的 Cookie 缺失、伪造、失效、撤销或认证版本不符；清理无效 Cookie |
| 403 `ORIGIN_REJECTED` / `CSRF_REJECTED` | 来源或 CSRF 检查失败，不继续密码验证或业务写入 |
| 404 `RESOURCE_NOT_FOUND` | 不存在或不属于当前用户的资源 |
| 409 `USERNAME_UNAVAILABLE` / `ALREADY_AUTHENTICATED` | 分别用于本地创建重名和有效会话重复登录；不开放远程用户名探测接口 |
| 422 `INVALID_REQUEST` | 字段、类型、长度或用户名格式非法；不得回显密码输入 |
| 429 `AUTH_RATE_LIMITED` | 超过限制，提供 `Retry-After`，不创建认证会话 |
| 503 `AUTH_UNAVAILABLE` | 持久化或认证组件不可用；不放行请求，不回显内部异常 |

普通输入校验错误也需要显式移除可能由框架自动附带的密码原值。原始错误堆栈只用于受控诊断，不能混入 API 或模型结果。

以下为验收清单；实际已执行项以 `tests/test_application.py` 和 `PROJECT_STATUS.md` 为准，不将每一行自动视为完整安全审计通过。安全边界既要测成功路径，也要直接绕过模型向服务提交错误输入。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | 创建、重复创建与重置模拟用户 | 无默认账号；重名不覆盖；散列和审计无明文密码 |
| A02 | 密码长度边界、空格与 Unicode | 1–128 字符按原值验证；不截断或规范化；非法输入不被回显 |
| A03 | 正常登录及会话固定尝试 | 创建新的认证秘密，旧预认证 Cookie 失效；数据库不存原 Cookie |
| A04 | 错误密码、未知与停用用户 | 相同 401 登录错误，未知用户走虚拟散列验证，均不获得身份 |
| A05 | 预认证及其过期 | 不能访问受保护资源；5 分钟边界失效；获取 CSRF 不提升权限 |
| A06 | 缺失、错误或跨会话 CSRF，以及跨域 Origin / 获取 CSRF 的伪造导航 | 写请求被拒绝；获取 CSRF 缺少自定义 Header 或跨站时不返回令牌、不替换 Cookie，无业务副作用 |
| A07 | 无 Cookie、伪造 Cookie、URL / Header 身份 | 受保护端点拒绝，不接受其他 Token 传递方式或自报身份 |
| A08 | 闲置超时边界 | 15 分钟边界失效；合法用户业务活动更新计时，模型与状态轮询不能续期 |
| A09 | 绝对超时边界 | 无论是否活跃，登录后 8 小时边界失效，客户端时间不起作用 |
| A10 | 退出与重复退出 | 当前会话持久化撤销；旧 Cookie 不可复用；其他浏览器会话不受误伤 |
| A11 | 服务重启 | 有效期继续按原时间计算，撤销、版本和限流窗口不清零 |
| A12 | 密码重置及用户停用 | 全部既有会话无效；重置旧密码不能登录；停用用户不能新登录 |
| A13 | 双用户访问同一测试资源 | 本人可访问；另一位用户与未知资源统一 404，无数据泄露 |
| A14 | 参数伪造 | 身份 / 角色字段被拒绝；模型或客户端信息无法覆盖 AuthContext |
| A15 | 凭据最小暴露 | API 错误、日志、状态快照、模型消息和工具结果均不含认证秘密 |
| A16 | Cookie 属性与传输配置 | HTTPS 默认保护开启；HTTP 例外仅显式 loopback；非允许 Host / Origin 不放行 |
| A17 | 重复失败、换 Cookie 与并发登录 | 限流按用户名和连接来源生效，不被并发或重启绕过；窗口结束可重试 |
| A18 | 退出 / 停用与并发请求 | 撤销提交后开始验证的新请求失效；不复活旧会话或串用其他用户身份 |
| A19 | 数据库或密码组件故障 | 返回不可用，不创建已认证会话，不采用默认身份；失败登录不留下半成品认证记录 |
| A20 | 登录与资金权限分离 | 登录或获取 CSRF 不创建预先授权、不改变资金状态，也不能开启自动操作模式 |

## 10. T03 的实现拆分

原计划将 T03 分为 A（本地用户与密码）、B（会话与认证 API）、C（资源隔离与集成验收）。本次在用户明确追加的可运行环境授权内，依次实现三部分并验证，再对接只读账户、工具和前端；实现与验收证据见项目状态。

这次交付仍需另一位开发者审查；不因此将整个认证清单、G0 或未来资金模块自动标为已验收。后续任务按执行计划和具体授权分步推进。

## 11. 设计依据

以下是技术参考，不是比赛规则，也不表示本项目已经通过安全审计。数值化会话和限流配置属于本项目选择。

- [OWASP 密码存储](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)：采用维护中的密码散列实现。
- [argon2-cffi 高层 API](https://argon2-cffi.readthedocs.io/en/stable/howto.html)：通过密码 API 完成散列、验证与参数升级。
- [OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)：服务端失效检查及会话生命周期设计。
- [OWASP CSRF 防护](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)：会话绑定的同步令牌与来源校验。
- [OWASP 身份认证](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)：统一失败语义与登录节流。
