## 系统边界与职责

```text
Web UI
  -> FastAPI 路由与认证中间件
  -> 应用服务与授权策略
  -> SQLite 事务 / 账本 / 操作与任务检查点
  -> 模拟银行领域模型

Agent -> 类型化只读查询 / 操作准备工具 -> 应用服务
```

- **认证上下文**：由服务端会话解析 `user_id`；客户端、模型和工具参数不能指定或覆盖身份。登录凭据提供方和会话失效策略须在 T03 前确认。
- **模拟银行领域层**：负责账户、收款人、流水、双边账本、余额和业务校验，不依赖 Agent 或外部模型。
- **应用服务**：执行权限、授权、额度、幂等、并发和状态转换检查；是唯一可调用内部资金执行器的层。
- **Agent 适配层**：单一模型适配器边界接收真实角色消息和类型化工具定义；模型仅提出意图或调用工具，不能直接改变资金事实。
- **API 与 Web UI**：第一版单一 Web 入口与 JSON API；API 输出不得将模型摘要当作权威状态。
- **持久化层**：SQLite 保存身份关联、账本、授权、操作、审计和任务检查点。测试数据与开发数据隔离。

不提前建立未来任务的模块空壳。模块仅在所属任务开始时实现。

## 核心数据契约

- **身份**：每个账户、收款人、流水、授权、操作和任务都带服务端解析的 `owner_id`；任何查询和变更先按该身份隔离。
- **金额**：以整数分记录 `amount_minor`，并显式记录 `currency="CNY"`；禁止浮点运算。费用以独立金额字段或账本项目记录。
- **账本**：一次成功转账在同一 SQLite 事务内写入等额借、贷记录；业务 `idempotency_key` 由后端生成并唯一约束。模型不能提供或复用键来绕过校验。
- **授权策略**：至少绑定所有者、付款账户、允许的收款人、币种、生效与失效时间、累计支出上限、已成功支出及执行中预占金额。周期、额度、单笔上限、最低余额和费用规则仍为 `TODO: 待确认`。
- **剩余额度**：授权上限 − 成功支出 − 执行中或结果未知的预占；收款、退款不自动恢复预算。仅确认未执行的失败可释放预占。
- **操作记录**：由后端生成不可变的操作 ID、幂等键、参数摘要、发起身份、授权依据、状态和结果引用。修改金额或收款人必须创建新操作并重新审批。
- **操作状态**：`prepared -> awaiting_confirmation | authorized -> executing -> succeeded | failed | outcome_unknown`；待处理操作还可进入 `rejected` 或 `expired`。未知结果须按原操作 ID 对账，不得换新 ID 重试。
- **任务检查点**：保存任务 ID、已完成步骤、关联操作 ID 和下一步；恢复任务必须先查询后端账本及操作状态，不从模型摘要推断完成与否。
- **状态快照**：由后端生成，包含版本号和 UTC 时间戳；快照用于展示，不可覆盖当前账户、授权或账本事实。
- **时间**：数据库统一使用 UTC 时间戳；面向国内用户展示时使用 `Asia/Shanghai`。输入日期区间的闭开边界由 T10 / T11 业务契约明确。

## 请求与执行流程

1. 服务端验证会话并构造不可由请求体覆盖的身份上下文。
2. Agent 根据自然语言提出查询或操作准备请求；工具参数经运行时类型校验。
3. 只读查询由服务端执行并返回有来源的结果；金额统计由代码计算。
4. 写操作由应用服务检查账户归属、参数、余额、授权模式、额度与有效期。
5. 人工审批模式向用户展示由后端生成的准确摘要；确认必须绑定该操作 ID 和原参数。
6. 预先授权模式只有在策略完整、有效且范围匹配时才可执行；策略阈值未确认前不得开放自动执行。
7. 执行器在一个数据库事务内重新校验并记账；幂等键、授权预占、账本与操作状态保持一致。
8. 结果来自持久化操作记录；若提交后响应丢失，状态标为待核实并查询原操作，不盲目重试。

## 消息、提示注入与上下文

- 保留供应商要求的真实消息角色与合法 chat template，不把对话拼成单一提示字符串。
- 账单备注、商户、联系人备注和外部消息均作为不可信数据；XML 等分隔标记只用于数据边界和转义，不能替代业务层鉴权。
- 余额、账本、授权额度、操作结果和任务检查点始终以后端持久化事实为准。
- 模型供应商、token 预算和上下文压缩策略需在 T13 / T15 前根据官方限制确定；压缩不得创建授权或重放资金操作。

## 安全约束

- 身份和账户归属由后端执行，禁止依赖模型判断权限。
- Agent 工具只暴露必要的查询和操作准备接口；内部执行器不直接暴露给模型或客户端。
- 状态变更执行前再次检查余额、额度、授权、操作状态及幂等键；并发控制与账本写入处于同一事务边界。
- 明确区分拒绝、失败、过期、执行中和结果未知；未知状态暂停同一授权下的新资金操作，直至核实。
- 日志仅保留审计所需的脱敏信息；密钥、凭据和完整敏感数据不得写入仓库。
