# 架构设计

## 设计状态

本文固化 T01 的第一版架构基线。按用户追加授权，已实现登录、查询及受控操作 Agent、银行业务 UI，以及模拟银行资金、恢复、授权和业务后端。支持逐笔确认后续办和用户显式选择预授权后的范围内执行；新闭环的真实模型验收、完整 T15 和队友审查仍待完成，比赛限制和阶段验收不因此自动通过。

T01-A 的[身份认证与会话契约](authentication.md)已落实为本地用户管理、Argon2id、持久化服务端会话、Cookie / CSRF 和资源隔离。测试结果与待审查项见项目状态；不是生产认证审计结论。

## 当前实现

- `config.py` / `store.py`：服务端配置与单机 SQLite，整数分、CNY、用户独立的虚构账户和流水。
- `auth/`：本机用户管理与服务端 Cookie 会话；`app.py`：同 Origin、CSRF、请求大小和资源归属校验。
- `agent.py`：五个固定查询工具后追加两个意图准备工具和操作查询；独立离线演示、Responses / Chat Completions 适配。模型不接触认证秘密或直接执行工具。
- `agent_operations.py`：对话派生稳定任务、业务参数派生步骤；串接人工等待、显式预授权、确定性执行及原操作回查。策略选择和任务暂停复用银行事件表持久化；未新增表或迁移。
- `tracing.py`：带请求 ID 的终端阶段日志、供应商可见思考 / 摘要、工具参数与结果；凭据脱敏、长度截断、内容开关，不输出加密思考。
- `observability.py`：可选 LangSmith SDK；通过上下文关联整轮 / 模型 / 工具，上传脱敏副本与实际 usage。默认关闭，32 轮有界队列由后台线程上传；模型消息、工具定义与业务执行不依赖追踪成功。连接配置与自检见 [LangSmith 接入](langsmith.md)。
- `banking/`：确定性转账、双边账本、预占预算、两种审批模式、检查点、恢复与审计、账单和登记订阅；所有写入仍经应用权限和原执行器复核。
- `web/`：FastAPI 同源提供原生 HTML / CSS / JavaScript；`banking.js` 提供资金表单、确认弹窗、授权管理和对话续办。借鉴 Astryx 的布局、表单、响应式和无障碍模式，没有引入 React 依赖。
- `conversations` / `chat_turns` 保存对话归属、完整回合和请求去重；短历史与字节预算只是初步边界，不是完整 T15 恢复机制。

启动与模型配置见 [本地开发](local-development.md)，资金契约、状态、统计口径、接口和显式数据库升级见 [模拟银行业务](banking-services.md)。已有数据库不在启动时自动增表；新库建立完整结构。

## 技术基线

| 项目 | 决策 |
| --- | --- |
| 语言与运行时 | Python 3.12+；用 `pyproject.toml` 声明最低版本，任务环境可使用更新的受支持版本 |
| 包与工具配置 | Python `pip` + PEP 621 `pyproject.toml`；不额外引入包管理器 |
| Web API | FastAPI；请求、响应及工具参数使用 Pydantic 类型校验。仅在对应实现任务引入运行依赖 |
| 存储 | 单进程 SQLite；使用 Python 标准库 `sqlite3`，不部署独立数据库服务 |
| 测试与静态检查 | pytest 与 Ruff；由 T02 建立最小工程配置 |
| Agent | 单主 Agent；模型供应商和版本待比赛约束核实后选择，先定义供应商无关适配边界 |
| 用户入口 | 第一版只建设一个本地 Web 入口；是否必须使用特定 APP / IM 渠道待核实 |
| 银行环境 | 自建模拟银行、合成数据；不接入真实银行、支付渠道或真实客户数据 |

Python 最低版本设为 3.12，本次实现环境实测 Python 3.13.12。运行时版本依据官方版本状态页持续复核：[Python supported versions](https://devguide.python.org/versions/)。

## 系统边界与职责

```text
Web UI
  -> FastAPI 路由与认证中间件
  -> 应用服务与授权策略
  -> SQLite 事务 / 账本 / 操作与任务检查点
  -> 模拟银行领域模型

Agent -> 类型化查询 / 意图工具 -> 应用服务
服务端绑定对话、持久任务与业务步骤
  -> 默认人工等待 -> 独立摘要确认 -> 执行 -> 回查 -> 继续原目标
  -> 显式选择预授权 -> 范围 / 余额 / 额度复核 -> 执行 -> 回查
任一步拒绝、失败、过期或未知结果 -> 停止后续步骤
```

- **认证上下文**：由持久化服务端会话解析 `user_id`，客户端、模型和工具参数不能指定或覆盖身份；本地模拟用户和会话失效策略按[认证契约](authentication.md)实现，T03 前须完成契约验收。
- **模拟银行领域层**：负责账户、收款人、流水、双边账本、余额和业务校验，不依赖 Agent 或外部模型。
- **应用服务**：执行权限、授权、额度、幂等、并发和状态转换检查；是唯一可调用内部资金执行器的层。
- **Agent 适配层**：单一模型适配器边界接收真实角色消息和类型化工具定义；模型仅提出意图或调用工具，不能直接改变资金事实。
- **API 与 Web UI**：第一版单一 Web 入口与 JSON API；API 输出不得将模型摘要当作权威状态。
- **持久化层**：SQLite 保存身份关联、账本、授权、操作、审计和任务检查点。测试数据与开发数据隔离。

不提前建立未来任务的模块空壳。模块仅在所属任务开始时实现。

## 核心数据契约

- **身份**：每个账户、收款人、流水、授权、操作和任务都带服务端解析的 `owner_id`；任何查询和变更先按该身份隔离。
- **金额**：以整数分记录 `amount_minor`，并显式记录 `currency="CNY"`；禁止浮点运算。费用以独立金额字段或账本项目记录。
- **账本**：一次成功转账在同一 SQLite 事务内写入等额借、贷记录；业务 `idempotency_key` 由后端生成并唯一约束。模型不能提供或复用键来绕过校验。
- **授权策略**：绑定所有者、身份版本、付款账户、允许收款人、CNY、创建和失效时间、累计 / 单笔上限、最低余额、允许操作与指定订阅。每次开启由用户显式填写并重新验证密码，无默认授权；费用固定为 0。同一授权跨会话和重启累计，不自动刷新预算。
- **剩余额度**：授权上限 − 成功支出 − 执行中或结果未知的预占；收款、退款不自动恢复预算。仅确认未执行的失败可释放预占。
- **操作记录**：由后端生成不可变的操作 ID、幂等键、参数摘要、发起身份、授权依据、状态和结果引用。修改金额或收款人必须创建新操作并重新审批。
- **操作状态**：准备后直接进入 `awaiting_confirmation` 或 `authorized`，授权后 `executing -> succeeded | failed | outcome_unknown`；待处理操作还可进入 `rejected` 或 `expired`。未知结果须按原操作 ID 对账，不得换新 ID 重试。
- **任务检查点**：保存任务 ID、已完成步骤、关联操作 ID 和下一步；恢复任务必须先查询后端账本及操作状态，不从模型摘要推断完成与否。
- **状态快照**：由后端生成，包含版本号和 UTC 时间戳；快照用于展示，不可覆盖当前账户、授权或账本事实。
- **时间**：数据库使用 UTC 时间戳；账单日期采用 `Asia/Shanghai` 自然日，开始日包含、结束日不包含，单次最多 366 天。

## 请求与执行流程

1. 服务端验证会话并构造不可由请求体覆盖的身份上下文。
2. Agent 查询并澄清目标；服务端按已认证对话绑定持久任务、业务步骤和用户在界面选择的策略，默认人工模式。所有参数经运行时类型校验，模型不能选择任务、步骤或授权。
3. 只读查询由服务端执行并返回有来源的结果；金额统计由代码计算。
4. 写操作由应用服务检查账户归属、参数、余额、授权模式、额度与有效期。
5. 人工审批模式向用户展示由后端生成的准确摘要；确认必须绑定该操作 ID 和原参数。
6. 预先授权只有在用户显式设置且策略完整、有效、范围匹配时才可执行；不根据模型建议自动生成额度。
7. 执行器在一个数据库事务内重新校验并记账；幂等键、授权预占、账本与操作状态保持一致。
8. 结果来自持久化操作记录；若提交后响应丢失，查询原操作会读到已提交的成功状态；中断遗留的执行中操作转为未知并对账，不盲目重试。
9. 人工批准成功后以稳定请求编号通知 Agent 回查原操作，再继续原目标；相同续办回放缓存。只有此前步骤全部成功才能新增下一步；策略失败持久暂停，必须由用户界面显式重新选择策略才解除此类暂停。

## 消息、提示注入与上下文

- 保留供应商要求的真实消息角色与合法 chat template，不把对话拼成单一提示字符串。
- 账单备注、商户、联系人备注和外部消息均作为不可信数据；XML 等分隔标记只用于数据边界和转义，不能替代业务层鉴权。
- 余额、账本、授权额度、操作结果和任务检查点始终以后端持久化事实为准。
- 模型供应商、token 预算和上下文压缩策略需在 T13 / T15 前根据官方限制确定；压缩不得创建授权或重放资金操作。

## 安全约束

- 身份和账户归属由后端执行，禁止依赖模型判断权限。
- Agent 工具仅暴露查询和意图准备；自动执行由应用依照用户显式选择的预授权进行，模型没有批准或直接执行工具。客户端写路由须经过身份、CSRF、操作状态和独立授权检查，不能绕过内部执行器。
- 状态变更执行前再次检查余额、额度、授权、操作状态及幂等键；并发控制与账本写入处于同一事务边界。
- 明确区分拒绝、失败、过期、执行中和结果未知；未知状态暂停同一授权下的新资金操作，直至核实。
- 日志仅保留审计所需的脱敏信息；密钥、凭据和完整敏感数据不得写入仓库。

任何待确认项若影响资金授权、身份隔离或竞赛合规，相应实现任务不得启动。
