# 架构设计

## 技术栈

| 项目 | 决策 |
| --- | --- |
| 后端与运行时 | Python 3.11+ 标准库 |
| 前端 | 原生 HTML、CSS 和 JavaScript，无构建步骤 |
| Agent 意图理解 | 本地中文规则匹配、金额 / 日期解析和联系人实体匹配 |
| 数据存储 | 进程内模拟状态；服务重启时恢复种子数据 |
| 测试 | Python `unittest`；Node.js 对前端脚本执行语法检查 |
| 部署 | 仅监听 `127.0.0.1` 的本地开发服务器 |

此选择针对本地演示和无密钥启动目标，不代表竞赛最终技术要求已经确认。真实比赛限制记录在 [比赛要求](competition.md)。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `src/ai_banking/agent.py` | 解析意图和实体，产生计划或查询结果，管理单次确认动作 |
| `src/ai_banking/domain.py` | 保存样例数据、计算汇总、执行业务校验、模拟操作并记录审计摘要 |
| `src/ai_banking/server.py` | 提供静态页面与 JSON API，限制请求体和监听地址 |
| `src/ai_banking/web/` | 展示总览、业务视图、对话计划、工具状态及操作确认 |
| `tests/` | 验证业务状态迁移、异常边界和本地 HTTP 契约 |

依赖方向为 Web 页面 → HTTP API → Agent → 模拟银行领域状态。Agent 不直接访问真实银行或外部模型。

## Agent 工作流

1. 接收本地页面或 `/api/chat` 的自然语言文本。
2. 根据场景规则识别转账、账单、理财、卡片、订阅或生日联动意图。
3. 校验联系人、金额、人数、产品和日期等必需参数。
4. 对只读查询返回解释、摘要与模拟工具调用记录。
5. 对会改变状态的任务返回执行步骤、影响说明和一次性待确认 ID。
6. 用户确认后由领域层重新执行余额、额度和持仓校验，再更新内存状态；拒绝或重复确认不会重复执行。

预约转账保存执行日期，在到期后首次读取状态时执行；可用余额不足时标记为失败。浏览器每 15 秒读取一次状态。演示不保证服务关闭期间持续调度，且重启会丢失数据。

## 本地 HTTP 接口

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/health` | 本地服务状态 |
| `GET /api/state` | 当前模拟账户及业务状态 |
| `POST /api/chat` | 请求体包含 `message` 文本 |
| `POST /api/actions/{id}/confirm` | 确认并执行单次待处理动作 |
| `POST /api/actions/{id}/reject` | 拒绝单次待处理动作 |
| `POST /api/reset` | 恢复种子数据并清除待确认动作 |

成功的业务响应可包含 `reply`、`intent`、`plan`、`tools`、`data` 或 `pending_action`。详细示例与运行方式见 [README](../README.md)。

## 数据与安全边界

- 金额使用整数分保存，避免浮点数运算造成分币误差。
- 静态数据全部虚构，接口不保存到磁盘；HTTP 服务仅接受本机回环绑定。
- 请求体限制为 64 KB，聊天文本限制为 2000 字；静态资源使用固定白名单路由。
- 设置 `Content-Security-Policy`、`X-Frame-Options`、`X-Content-Type-Options` 和 `Referrer-Policy`。
- 不收集认证信息，不记录聊天请求正文；资金和状态变更在执行前展示确认及风险说明。
- 这是可交互演示，不具备真实银行要求的鉴权、授权、密钥管理、交易幂等持久化或监管能力。

## 后续待确认

- 正式运行时的模型成本、隐私、风控及交易审批要求。
- 任何架构扩展须先核实比赛规则和产品需求，再决定依赖及接口。
