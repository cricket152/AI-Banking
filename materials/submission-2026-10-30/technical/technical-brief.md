# 技术文档素材初稿

## 项目定位
AI-Banking 是面向个人用户的本地模拟银行 Agent。以自然语言查询和受控代办连接账单分析、订阅管理与内部转账，让用户看清依据、选择方案、确认动作、核对回执。实现重点是有限业务能力内的权限和状态约束，不是接入真实金融机构。

## 已实现能力
- 账单：自然日闭开区间，分类/商户/月度汇总，前一等长区间对比，退款和转账分列，可分页回查原流水。
- 异常线索：非转账单笔支出≥1000元；前期同类至少3笔时，单笔>历史较低中位数3倍且≥100元。只提示人工核对，不判定欺诈。
- 订阅：最近一年同账户同商户至少3次等额支出、间隔25–35天、最近45天有扣费，产生带原始流水的候选。显式确认后登记；取消不退款，无后台自动扣款。
- 收款人：本人账户、密码再认证载入的独立虚构联系人、备注、名称/备注/尾号搜索。同名需澄清；不支持手机号或真实好友认证。
- 转账：人工确认和明确预授权共用原执行器；整数分、CNY、费用0、双边账本和幂等。
- 联动：用户选定订阅、账户、收款人和固定金额，预览未来少支出与当前现金影响后保存方案；执行顺序和参数在准备事务中强制验证。
- 理财/卡片：Agent仅查询/解释模拟理财与脱敏卡片数据；申购、赎回、卡片申请/调额/冻结/解冻/挂失由界面发起，卡片写操作需密码再认证。

## 架构与职责
原生 Web 由 FastAPI 同源提供，Pydantic 校验输入；服务端持久会话解析身份，单主 Agent 通过12个类型化工具查询或准备业务；AgentOperations 绑定对话、任务、步骤和用户选择的策略；Bank 在 SQLite 事务内校验归属、余额、授权与幂等并记账。余额和完成状态以持久化账本、操作为准。Agent对卡片、日期场景计划和理财数据只读/解释；这些业务的写操作由界面发起，卡片操作另需密码再认证。
模型供应商通过 Responses / Chat Completions 适配，离线模式单独标记。可选 LangSmith 仅上传受配置约束的追踪副本（可包含问答与工具内容），不参与账本事实，不是可靠审计源。
架构图展示核心控制分工，不表示多个独立部署的微服务。当前为单机、单进程、回环 HTTP 开发环境。

## 核心机制与算法
1. 金额不使用浮点数；一次内部转账同事务写等额借贷流水及操作状态。
2. 服务端按对话与业务参数派生任务/步骤，重复请求复用原操作；未知结果按原编号核查，不换号重发。
3. 授权剩余额度=累计上限−成功支出−执行中/未知结果预占；收入不补回预算。每次执行复核账户、对象、币种、时间、单笔/累计上限及最低余额。
4. 订阅取消后转固定金额的工作流由界面选择并落库；服务端预览摘要校验证据，禁止跳步骤、改参数或用新步骤编号重做计划内付款。创建工作流不是授予权限。
5. 日期场景计划只保存日期与预算；创建时校验当时可用余额但不冻结/预留资金。达到可操作时间后须用户在界面手动点击按钮，产生的操作仍待确认；不自动提醒或下单。
6. 上下文最多读取60个成功回合，默认近期12轮原文，旧问答80/140字符确定性摘录，默认32000估算tokens。超预算停止新增操作，任务状态从后端回填。不是无损摘要，也不是供应商精确tokenizer。

## 证据与不足
当前工作树235项pytest通过（包含前端浏览器冒烟1项），模型HTTP由测试替身提供；源文件 `tests/` 可复现。另在新建Python 3.13 venv按 `requirements-dev.lock` 安装 `.[dev]`，`pip check`通过并完成39项核心/前端定向测试。最低要求Python 3.12但本机无该解释器，未实测；上述验证不等于全新机器或其他OS验收。历史36条真实模型评测35条结构检查通过，1条被输出预算未完成保护拦截；不能作为语义成功率。本轮未配置可用真实模型凭据，新增联系人、固定方案、卡片、日期场景和理财专项真实模型评测未运行。
无真实支付、定时转账、AA收款、无人登录后台执行、通用任意规划器、RAG或多Agent。三场景不等于完整覆盖图中每个子功能，生日资金冻结和预订尚未实现。
