# 核心机制撰写素材

以下是实现说明与排版用伪代码，不是未经验证的新算法或研究原创性声明。实现以源码快照为准。

## 账单区间与异常线索

界面输入开始日期和“结束日期（含当天）”，服务端转换为 Asia/Shanghai 自然日的左闭右开区间 `[start, end)`。前期为 `[start − (end − start), start)`，保持相同天数，不固定为上月或去年同期。同一事务读取两期，支出取负数流水的正金额、退款独立列示、转账不计入消费；按原分类和商户聚合。

异常线索之一是单笔非转账支出至少100000分。另一条规则按前期同类支出构造样本，至少3笔时取 `median_low`：当本期单笔至少10000分且严格大于中位数3倍，提示人工核对。偶数样本用较低中位数，不要画成均值或机器学习风险分数。报告保留规则和原流水，不自动止付或认定欺诈。

依据：`src/ai_banking/banking/reports.py`；图：03、04。

## 订阅线索到显式登记

```text
按本人账户 + 商户分组最近一年的支出
仅保留至少3笔、金额完全相同的组
要求相邻支出日期间隔都在25–35天、最近45天有支出
排除已经登记的同账户同商户（包括已取消记录）
返回原流水、金额、日期、候选编号和证据摘要

用户展开证据并显式确认
在事务内重新识别候选、比对摘要
证据变化则拒绝；重复/并发确认复用登记结果
登记原订阅表，不扣款、不创建授权、不触发后台定时任务
```

下次日期按最近一笔加一个日历月估计，月末按目标月最后一天裁齐。它不是已存在自动续费合约的证明，也不是实际定时扣费服务。依据：`banking/subscriptions.py`；图：05。

## 幂等与双边记账

```text
用户身份 ← 服务端会话
任务 + 步骤 + 规范化参数摘要 → 原操作
若同一标识但参数变化：拒绝冲突
若已有操作：回查该编号，不重新准备一笔相同付款

执行前：复核会话、操作状态、期限、权限和余额
事务内：扣付款账户、加收款账户
        写金额相反的双边账本与账户流水
        结算额度/预占并提交 succeeded
```

金额为整数分，模拟内部转账币种CNY、手续费0。任何失败与未知结果均按原操作追踪；页面文字不能代替账本。依据：`banking/service.py`、`banking/schema.py`。

## 明确预授权的逐次复核

设累计上限为 `L`，已成功支出为 `S`，执行中/未知预占为 `R`，本次金额加费用为 `C`。准备预占时必须满足 `S + R + C ≤ L`，同时 `C ≤ 单笔上限`；授权还限制本人付款账户、操作类型、收款人/订阅集合和有效期。来源账户余额扣除其他预占与本次金额后，不能低于最低保留余额。

授权所属身份版本失效、过期、被撤销或范围不匹配时拒绝。存在相关未知结果时暂停新支出，不因收入到账恢复累计预算，也不因开新对话或重启恢复额度。授权可以减少交互次数，不能证明模型理解正确。

依据：`Bank._policy`、`Bank._available`、`Bank.prepare`、`Bank.execute`；图：14。

## 操作状态与恢复

人工模式从 `awaiting_confirmation` 开始，独立挑战校验后进入 `authorized`；拒绝进入 `rejected`。预授权模式经策略复核后可以进入 `authorized`。执行路径为 `authorized → executing → succeeded`，明确业务失败为 `failed`；到期可变为 `expired`。中断或结果无法确认时保留 `outcome_unknown`，按原操作核对，不能盲目新建付款。

固定方案把步骤和参数持久化到应用任务与对话状态中；准备事务禁止跳过前一步、改变对象/金额或用新步骤编号重做。一个独立步骤成功后，不因后续失败自动撤销已生效动作。图：08–12。

## 有界上下文

保留固定系统约束和当前应用状态，在预算内加入近期原始回合、旧回合确定性摘录以及经过长度限制的工具返回。默认最近12轮、总预算32000估算tokens、旧摘要预算800、输出预算1500、工具预留4000，工具结果默认最多6000字符。CJK字符约1 token，其他字符约4字符/token，并加消息开销；不等同供应商实际计费token数。

压缩会损失细节；权限和完成状态仍从后端核验。超预算停止新增操作，不能通过删除安全系统约束来继续付款。依据：`context.py`、`agent.py`、`config.py`；验证见 `tests/test_context.py`。

## 日期场景计划的边界

日期场景计划只保存日期与预算。创建时校验当时可用余额，但不冻结资金、不创建预算预占或付款授权。到可操作时间后必须由用户在界面手动点击下单按钮；该动作只准备待确认操作，后续仍走既有确认流程。没有自动提醒、定时扣款或外部商户下单。Agent可读取/解释计划状态，但不能创建、修改或下单；相关写操作由界面发起。

这与上面的“取消所选订阅后转固定金额”多步骤工作流不同，不应将两者合并描述。

## 可以突出哪些工程亮点

1. 分析结论可以回到流水证据，而不只给一段模型解释。
2. 同名对象、当前资金和未来节省分别表达，减少误操作入口。
3. 权限与资金事实独立于模型回答，人工和预授权共用同一执行约束。
4. 固定多步骤方案可保存、回查并避免重复付款，未知结果保守暂停。
5. 有界上下文配合持久化检查点，控制输入长度，同时明确压缩不是无损记忆。
